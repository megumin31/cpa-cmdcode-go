# 标签驱动发版

版本以 Git tag 为准，无需手动修改源码版本，也无需点击“创建 Release”。
可以直接给已经测试通过的 commit 打标签，不需要空提交；该 commit 必须已包含新版工作流。

1. 推送待发布提交，等待普通 CI 通过。
2. 选择尚未使用的 vX.Y.Z 或 vX.Y.Z-rc.1 标签，指向这个确定的提交：

   ```sh
   git tag -a vX.Y.Z <测试通过的commit> -m 'Release vX.Y.Z'
   git push origin vX.Y.Z
   ```

3. 标签推送后重新完成 Linux amd64、arm64 原生构建与完整验证。
   双架构均成功才打包，创建或复用草稿 Release，上传并校验全部资产后发布。
   带后缀的标签自动标记为预发布。

分支推送、PR 和手动分支运行只做 CI，不发版；没有 release.published 第二入口。
构建时由标签通过 Go 链接参数注入版本。为兼容 CPA，内部库名保持
cmdcode-go-vX.Y.Z.so，预发布也使用纯数字 ABI 版本；完整标签保留在 build_tag、
压缩包名和发布清单中。开发构建使用 0.0.0 和 build_tag=dev，不能当正式发布。
标签构建会在相同源码 commit 上重新注入发布元数据，因此字节与之前开发构建不同。

## 资产与校验

发布包含对应标签的 amd64、arm64 压缩包、SHA256SUMS 和 release.json 完整清单。
安装前校验外层及解压后的 SHA256SUMS，选择正确架构。
不要给内部 .so 改名添加架构或预发布后缀。压缩包保留 LICENSE、插件/构建元数据、
ELF/glibc 报告、干净提交记录及逐文件校验和。详见 [CI](CI.md)。

## 失败与重试

测试、构建或打包失败不发布；上传失败保留草稿，可重试失败的 job。
相同资产校验后跳过，不覆盖不同的历史资产。已发布的 Release 只有在全套资产完全
一致时视为完成，不补写或修改。只允许清理草稿中空的失败上传占位项。
持续检查标签仍指向原提交，不创建或移动标签。完整重跑可能改变运行来源元数据，
优先重试失败 job。资产先上传再发布，兼容不可变 Release。

测试包含模拟 GitHub 和合成 ELF 打包场景、真实 Go 链接注入；原生门禁保留
Go 测试/race/vet、模型目录、工作流、C ABI 生命周期和构建来源验证。
这些测试不调用真实上游推理，也不证明账户额度或实际模型可用性。

## 模型数据与发版

`models-data` 分支独立更新，不创建版本标签或触发插件发布。每个代码版本的内置清单固定在
`data/models.snapshot.json`，由 `--from-json` 离线生成 Go 兜底并由完整质量门校验。
构建时不下载可变数据分支。首次迁移应先发布数据快照，再部署使用新默认地址的插件。
